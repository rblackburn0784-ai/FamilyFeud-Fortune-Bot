# V1.3 Modularisation Notes

V1.3 starts the move away from one very large `main.py` by adding a small `feudbot/` package and a reusable health command module.

## Added

- `feudbot/__init__.py`
- `feudbot/version.py`
- `feudbot/diagnostics.py`
- `feudbot/health_command.py`
- `tools/apply_v1_3_modularisation.py`

## Health command

The new health command module registers an in-Discord command:

```text
/feud_health
```

It reports:

- bot version
- uptime
- Discord latency
- server count
- active rounds
- question pool size
- custom question count
- SQLite status
- board template status

## Applying the integration patch

Because the current bot still lives in a large single-file `main.py`, V1.3 includes a safe patcher rather than a broad manual rewrite.

Run this once from the repository root:

```powershell
.\.venv\Scripts\python.exe tools\apply_v1_3_modularisation.py
```

Then run the healthcheck:

```powershell
.\.venv\Scripts\python.exe tools\healthcheck.py
```

Then start the bot normally:

```powershell
.\.venv\Scripts\python.exe main.py
```

## Next modularisation targets

Recommended V1.4 split:

```text
feudbot/config.py
feudbot/models.py
feudbot/storage.py
feudbot/questions.py
feudbot/scoring.py
feudbot/rendering.py
feudbot/views/
feudbot/commands/
```

The safest order is storage and diagnostics first, then command groups, then views and game flow.
