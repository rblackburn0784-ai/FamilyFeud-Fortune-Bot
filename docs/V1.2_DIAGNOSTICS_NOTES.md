# V1.2 Diagnostics & Operator Tools

V1.2 is a safety-first improvement pass focused on making the bot easier to run, check, and maintain before game nights.

## Added

- `tools/healthcheck.py`
  - Local pre-flight checker.
  - Does not connect to Discord.
  - Does not require a real bot token unless checking `.env` completeness.
- `tools/README.md`
  - Documents how to run the tool.
- `VERSION`
  - Updated to `1.2.0`.

## Healthcheck coverage

The healthcheck verifies:

- Required source files exist.
- `.env.example` exists.
- `.env` contains a non-placeholder `DISCORD_BOT_TOKEN`, if `.env` exists.
- `main.py` compiles.
- Built-in question JSON files parse correctly.
- Question packs have plausible question/answer structures.
- Runtime JSON files are either absent or valid JSON.
- `fortune_bot.sqlite3`, if present, can be opened.
- `assets/game_board_template.png`, if present, is detected.
- Slash commands can be statically detected from `main.py`.

## How to run

From the project root:

```powershell
.\.venv\Scripts\python.exe tools\healthcheck.py
```

Or:

```bash
python tools/healthcheck.py
```

## Why this came before a full code rewrite

`main.py` is currently a very large single-file bot. V1.2 avoids risky logic churn and gives you a reliable way to check the project before bigger structural work.

Recommended next patch:

- Start modularising the bot into small files.
- Add an in-Discord `/feud_health` command once the diagnostics logic is moved into an import-safe module.
- Move persistence toward SQLite-first storage.
- Add board themes and game-night presentation upgrades.
